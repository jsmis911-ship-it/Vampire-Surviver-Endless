# 局域网双人合作测试版

## 运行

主菜单右下角「多人游戏 · 测试版」进入独立房间界面。双方使用同一份 Windows 构建：

1. 房主选择角色，点击「创建房间」，把显示的局域网 IPv4 地址告诉队友。
2. 队友选择角色，输入房主地址并点击「加入房间」。
3. 双方点击「准备」，房主点击「开始合作」。

默认 TCP 7777。两台设备需要网络互通，房主程序需要通过系统防火墙。
本机双进程测试可填写 `127.0.0.1`。无云服务、账号或自动房间发现。

WASD / 方向键移动，Shift 冲刺，鼠标瞄准，左键发动闪电。
靠近倒地队友（2.5 世界单位内）按住 E 三秒可救援，恢复一半生命并获得一秒保护。
Esc 打开本地菜单，战斗继续。两人倒地时失败，最终 Boss 死亡时共同通关。

团队共享经验和等级，每次升级暂停战斗，双方各自三选一后继续。
宝箱在房主端为拾取者即时随机发放一项强化；治疗归拾取者，磁铁吸引经验。

## 架构与单人兼容

- `LanSession`：连接握手、房间准备、加载屏障、输入归属、共享经验、升级轮次、倒地救援和结算。
- `LanTransport`：独立的 TCP 分帧传输，不依赖 Unity。工作线程只读写字节，主线程解析并执行游戏行为。
- `LanProtocol`：输入、房间消息、对局状态和显示快照的数据结构。
- `LanWorldView`：房主采集显示状态，加入者只创建被动 SpriteRenderer。加入者不创建角色、怪物、武器的战斗脚本，因此不会重复扣血或掉落。
- `LanOverlay`：独立 Canvas，房间、HUD、升级和结果不会进入单人的弹窗栈。
- `LanAssetCatalog` / `LanBuildTools`：以资源 GUID 和子资源 ID 固定精灵顺序；构建前自动重建资源目录，避免同名素材在两端映射不同。

多人入口沿用 GameScene 的摄像机和地图资源，但有独立初始化分支。房主实例化两份原角色，只有一个刷怪器工作。
原武器读取父级角色属性；多人输入、瞄准和规则通过会话接入。单人不创建 LanSession，继续原来的场景和结算流程。
房主为两名玩家各维护一组循环地形，第二组仅保留碰撞，避免队友离开房主附近后缺失地形判定；加入者地形仅用于显示。
原有对象池仍用于房主的战斗对象；每次回收重置穿透和拾取状态，显示快照负责加入者的生成/移除。

TCP 控制帧可靠有序；状态发送和接收各保留最新一份快照，避免慢速接收者积压旧场景。
房主目标 20 次/秒发布完整状态，加入者目标 30 次/秒发送输入；最大单帧 1 MiB，控制队列最多 32 条。
输入按连接绑定到第二名玩家，检查序号、有限数值和方向长度；停止收到有效输入 0.5 秒后归零，通信超时 15 秒结束会话。
冲刺和闪电发送递增请求计数，实际冷却和伤害由房主判定。升级按轮次验证并只应用一次。

## 构建与验证

Unity 菜单 `Tools > Multiplayer > Build Windows Test Player` 生成 `Builds/LanTest/VampireCoop.exe`。
构建包含主菜单和原游戏场景。将生成目录整体复制到另一台电脑，不能只复制 exe。
修改美术资源后可运行 `Tools > Multiplayer > Rebuild Asset Catalog`；构建时自动执行。

Development 构建可用两个进程执行端到端测试：

```text
VampireCoop.exe --lan-smoke-host
VampireCoop.exe --lan-smoke-client
```

`Assets/Tests/LanSmokeDriver.cs` 仅在 Editor / Development 构建存在，普通运行不启动。
测试覆盖真实握手、加载、输入移动、武器归属、重复致命伤只掉落一次、真实碰撞拾取升级、双方选择恢复、远程 E 救援、原 Boss 通关、返回主菜单。
测试为控制场景会临时提高生命值、停止刷怪并生成指定怪物；这些操作不会发生在正常对局中。
报告和截图写入工作目录下的 `Logs/lan-smoke-*`。

`Tools/lan_wire_smoke.py` 是额外的协议测试客户端，支持拆分 TCP 帧发送以检验粘包/半包处理。
安装 .NET 9 SDK 后，可运行 `powershell -File Tools/Test-LanTransport.ps1`：测试非法帧、半包/粘包、端口复用、状态突发、第三人连接和断开处理。运行前关闭占用 7777 的游戏房间。

## 当前边界

这是 Windows 局域网初版。暂不支持中途加入、断线重连、房主迁移、公网匹配或存档恢复。
房主退出/断线会结束本局。网络层先采用 TCP；高延迟或丢包下可能出现卡顿，尚无本地移动预测。
显示快照暂时同步精灵和战斗状态，加入者的独立音效事件、伤害飘字和部分非精灵表现仍需后续补齐。
同步频率、JSON 全量快照和场景精灵扫描适用于初始 50 怪物上限；扩大规模前应测量并改为实体注册、二进制增量和更合适的传输。
后续可在传输和显示层替换为 Mirror/KCP，保留房主战斗和合作规则。
